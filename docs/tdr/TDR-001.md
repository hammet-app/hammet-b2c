# TDR-001 — Deferred B2C Cart Functionality

**Category:** Architecture  
**Status:** Deferred  
**Priority:** Medium  
**Owner:** Frontend  
**Review Date:** 2026-12-01

## Context

The current B2C cart implementation prioritizes the functionality needed for the initial rollout rather than implementing the complete cart lifecycle and synchronization model.

The cart is stored in Dexie (IndexedDB) locally. The current implementation has two known limitations.

## Debt 1: No Clear Cart Function

**Current State:**  
The cart does not have a dedicated clear function. Items must be removed manually.

**Why Deferred:**  
The current implementation prioritizes the core purchasing functionality required for the initial rollout. A dedicated clear function is not currently considered essential to that scope.

**Decision:**  
Leave the cart without a clear function for now.

**Fix Trigger:**
- Users need a convenient way to empty their carts.
- Cart management becomes a more prominent part of the purchasing experience.
- The cart implementation is revisited for broader improvements.

## Debt 2: No Dexie-to-Backend Cart Synchronization

**Current State:**  
The cart is stored locally in Dexie, but synchronization from Dexie to the backend has not been implemented.

**Why Deferred:**  
The immediate focus is on supporting the purchasing functions required for the initial rollout. Given the expectation that a user will most likely be purchasing a course for one school at a time, implementing a complete synchronization flow is not currently a priority.

**Decision:**  
Keep the current local cart implementation and defer Dexie-to-backend synchronization until the product requirements justify it.

**Fix Trigger:**
- Users need to resume carts across devices or browser sessions where local state is unavailable.
- Cart persistence across devices becomes a requirement.
- Backend-side cart management becomes necessary for the purchasing flow.
- The current local-only approach creates measurable usability or reliability problems.

## Consequences

**Accepted for now:**
- Users must remove cart items individually.
- Cart state is not synchronized from Dexie to the backend.
- Cart persistence and recovery are limited by the local storage implementation.

**Expected benefit:**
- Less implementation complexity during the initial B2C rollout.
- Engineering effort remains focused on the purchasing functionality currently required.

## Review Notes

At the review date, reassess both limitations against actual purchasing behavior and product requirements. Implement them separately if their requirements or priorities differ.
